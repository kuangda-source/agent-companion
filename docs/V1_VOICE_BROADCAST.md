# V1 语音播报与增量会话记忆

2026-11-08 设计，2026-11-09 更新软件准备进度。保留现有 Gateway、Mastra、共享 LVGL 界面和三种连接方式；V2 共享房间仍延后。当前尚未完成板端音频通道和实际听音验收。

## 范围

先做单向播报：对话本轮结束及简要结果、等待用户输入或审批、需要关注的实验进展、重复故障，以及经确认的额度重置／恢复。语音问答、ASR、声纹、唤醒和连续对话不进入本轮实现。

Mac 是采集、记忆、事件决策和 TTS 的主机；桌面监视器是默认声音输出端。Mac 在宿舍、监视器在工位时仍须能播放。Mac 本机试听只作为显式测试操作，不自动代替设备播放。

## 设计前基线

| 能力 | 当前实现 | 需要补齐 |
| --- | --- | --- |
| 增量读取 | `assistant-source.ts` 保存 inode、offset、size、mtime；`assistant.ts` 将游标和滚动摘要持久化到 SQLite | 分离可靠摄取位置与摘要消费位置；按会话更新结构化事实 |
| 长历史 | 首次大文件读取首尾节选；突增超过读取预算时也可能跳读，并标注 partial | 保留覆盖范围；正常增量分页消费，不能跳过尚未保存的增量后宣称已读 |
| 摘要 | 旧摘要＋新增公开正文，校验来源引用后提交；无变化跳过模型请求 | 当前任务、最新结果、未解决问题分别更新；避免一个会话变化导致全部会话重写 |
| 通知 | DSH 事件合批；稳定主题 key、关注事项周期和持久化文字通知去重 | 独立语音优先级、有效期、设备播放状态和去重账本 |
| 等待状态 | 协议及 LVGL 支持 `waiting_user`：黄色“等待输入”、等待计数和角色动作 | Codex 采集器目前只处理开始／结束等事件，未识别明确输入／审批等待；不能声称已支持可靠提醒 |
| 音频 | 现有板级 BSP 提供 ES8311、I2S 和扬声器初始化 | 当前应用未接入音频播放；须验证实际扬声器和音量 |
| 传输 | USB AC1、LAN／relay 同步 JSON 视图及应用 ACK | 音频分片和播放回执尚未实现；不能将音频直接塞入现有整包视图 |

## 每个会话的增量记忆

应用自有 SQLite 是规范数据源；Mastra 消费有限上下文，不负责决定哪些科研事实已经成立。Letta 后续通过现有记忆端口适配。

每个 `session_id` 保存：

- `source_generation`：来源身份、inode／轮转标识；替换或截断后不能沿用旧字节偏移。
- `read_cursor`：已安全写入本地增量收件箱的完整记录位置。
- `summary_cursor`：已通过模型输出及引用校验、提交进记忆的批次位置。
- `current_task`：目标、当前阶段及轮次；任务变化生成修订，不靠整段摘要覆盖猜测。
- `latest_results`：近期结果、来源时间、引用和证据层级；区分计划、Agent 报告、独立验证、用户验收。
- `open_questions`：未解决事项的稳定 ID、状态、提出和解决依据；摘要遗漏不代表解决。
- `pending_requests`：来源明确的输入／审批请求 ID、是否阻塞、响应状态；与模型提取的普通未解决问题分开。
- `rolling_summary` 和历史修订：压缩历史背景，保留可追溯引用及覆盖范围。

摄取先持久化去重后的公开消息，再推进 `read_cursor`；摘要、事实修订、引用及 `summary_cursor` 原子提交。TTS 或推理失败均不回退摄取，也不丢失尚未摘要的消息。重启后继续消费相同批次，避免重复写记忆。

每次请求只发送受影响会话的旧结构化状态＋未消费增量＋少量相关引用。按有限预算分页处理，不把几十万 Token 的历史重发给模型。首次历史节选必须标注 partial；需要时在后台分批补历史，与实时通知分开，补入的旧事实不触发新播报。

项目级简报在会话记忆更新后合批生成，只取相关会话摘要。当前最近天数／会话数量上限仍是覆盖边界，不能把范围外的项目说成“全部已监控”。

## 播报事件、优先级与去重

| 优先级 | 事件 | 默认表现 |
| --- | --- | --- |
| P0 | 明确需要用户回答／审批、实际阻塞或重复故障 | 排到下一条；及时提醒，不反复朗读；V1 先不打断正在播放的一句话 |
| P1 | 对话本轮结束、重要实验里程碑／结果 | 合并近邻事件，播报会话名＋简要结果；不逐条朗读工具过程 |
| P2 | 官方新观测确认额度重置／恢复 | 一次简短提醒；不同额度窗口同时变化可合并 |

事件结构至少包含 `event_id`、`session_id`、`turn_id`、`kind`、`topic_key`、`cycle`、`priority`、`source_ids`、`source_at`、`revision`、`expires_at`、`supersedes`。设备投递另外保存 `delivery_id`、目标设备、音频散列、播放状态和回执，不依赖 TTS 文本完全相同来去重。

- 同一会话、同一任务、同类故障使用稳定故障指纹；达到重复阈值后只播一次“任务出现重复错误”。后续十次同类失败只更新计数。明确恢复、用户处理或实质状态改变后关闭该周期；新周期才可再提醒。跨会话故障不能被误合并。
- 等待输入必须基于明确请求及其 ID；收到相应回答或明确取消后立即撤销尚未播放的提醒，阻塞请求恢复也以来源确认的状态为准。异步提出问题后 Agent 仍在继续工作，保留运行状态并单独显示待答提示，也可对该请求提醒一次，不直接判为阻塞等待。不能根据“最后一句像问题”或长时间无消息推断等待。
- 明确区分“定时任务等待调度”和“会话等待用户”。暂停的计划仍遵循现有隐藏规则，不生成等待输入播报。
- 同一 `completion_event_id` 只播一次。结束表示本轮结束，不能等同于整个项目或实验成功。当前轮次摘要尚未生成时延迟短暂合并；模型不可用则只播确定的“本轮已结束”，不套用上轮结果。
- 实验进展必须有新引用且达到重要程度；普通编译、工具调用和重述旧结论不播。Agent 自述结果用“报告……”表述，不能升级为独立验收。
- 额度倒计时归零只触发核查，绝不直接触发“已重置”。新鲜官方观测确认窗口切换且额度恢复后再播；只能证明余额增加时说“额度已恢复”，不猜测原因。首启读取已有额度作为基线，旧缓存不补播。保留现有额度查询频率。
- 默认建议同会话 P1 合并窗口 20 秒、全局播报间隔至少 15 秒；等待提醒 2 分钟过期、结束／进展 10 分钟、额度恢复 15 分钟。均是待实测调整的初值。播放前重新检查是否已回答、解决、过期或被新版本取代。
- 重启不重播已完成记录；离线重连不倾倒历史队列。未播且仍有效的重要事件合并后补一次，其余留在文字消息区。

## Mac 生成、设备播放

链路：`只读来源 → 增量记忆／确定性状态事件 → 有优先级的持久队列 → 脱敏短播报稿 → TTS → 音频传输 → 板端播放器 → 播放回执`。

TTS 采用独立适配器，不绑在摘要模型上。服务地址、声音及 Key 在 Mac 设置，凭据不传给板子或中转。外部 TTS 只接收最终播报短文；不发送完整历史、工具日志或实验文件。具体服务／音色按用户配置；未开启生成时不调用 TTS。

第一阶段候选传输格式为 16 kHz、单声道、16-bit PCM，最终以板级 codec 实测为准；每秒约 32 KB，15 秒约 480 KB。Mac 统一转码，板端不必先引入复杂音频解码器。BSP 默认是 22050 Hz，播放器必须显式协商／配置采样率，不能直接按默认速度播放 16 kHz 数据。

先复用 USB、LAN、relay 的设备身份和鉴权，增加有版本的音频控制与分片协议。升级 relay 和两端的包类型校验，不开放匿名音频 URL，也不让板子访问 Mac 的 loopback 管理接口。语音主机密钥与设备令牌继续分离。

- 控制字段：音频 ID、事件／投递 ID、codec、采样率、通道、长度、散列及有效期。
- 分片带序号、长度和校验；有 ACK、有限重试、背压和取消。设备只接受与当前授权播放任务匹配的数据。
- 视图、触摸、心跳和熄屏／亮度命令优先于音频；有界环形缓存＋独立 I2S 播放任务，不阻塞 LVGL。
- 接收成功、开始播放、播放完成是不同状态；UI 视图 ACK 不能算语音播放完成。
- 网络无法保证严格的物理“恰好播放一次”：设备持久化有限投递账本；已经开始但缺少完成回执的任务记为结果未知，默认不自动重播，允许手动重播，避免断线重复响。
- USB／LAN／relay 切换沿用同一投递 ID，不产生第二份提醒。旧固件未声明音频能力时仅保留文字，不影响原监控功能。

板端工具提供音量、静音／停止、试听与重播最近一条；Mac 提供总开关、类别开关、安静时段和默认输出设备。安静时段默认抑制语音；是否允许指定 P0 越过静音由用户明确配置。显示器跟随熄屏与静音分开设置，避免自动改动现有行为。

## 分步实施和验收

1. 补齐 Codex 明确等待／审批信号：合成测试覆盖提出、回答、恢复、取消及重启；真机会话与板端黄色状态核对。不能通过写入或修改原 Codex 会话来测试。
2. 结构化会话记忆和两个游标：验证单会话增量更新、长历史预算、跨页无丢失、截断／轮转、失败重试、引用和更正追踪。
3. 语音事件队列：以 MOCK 验证十次同类故障只出一次、解决后新周期、重复完成、旧摘要、静音、过期、重启及额度确认。
4. 先用测试 PCM 打通板级扬声器，再经 USB 发送；保持 UI／触摸和心跳正常。完成后接 TTS，并检查听感、采样率、音量和播放回执。
5. 验收 LAN，再将 Mac 与监视器放到不同网络验证 relay：真实由监视器发声、Mac 不作自动播放回退，断线与连接切换不重复播报。
