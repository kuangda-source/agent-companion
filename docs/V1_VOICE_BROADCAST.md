### 两条事件入口，共用一个队列

1. **确定的状态事件**：明确输入／审批请求、任务本轮结束、连续故障、官方新额度观测，由现有采集器和规则生成提醒；这条路径不依赖摘要模型是否可用。
2. **需要理解的实验进展**：只把新增公开内容送入现有增量记忆，复用已通过来源校验的结果、决策与阻塞信息，生成短播报稿。没有实质变化、只有计划或普通工具过程时保留文字即可。

| 优先级 | 纳入条件 | 示例措辞 |
| --- | --- | --- |
| P0 | 明确等待回答／审批，或确实需要用户处理的阻塞、同类重复故障 | “示例任务正在等待你确认。” |
| P1 | 本轮结束、有新来源的重要实验结果或里程碑 | “示例实验本轮结束，报告了新结果，尚待验收。” |
| P2 | 官方新鲜额度观测确认容量恢复 | “示例 Agent 的本周额度已恢复。” |

普通决定不自动提升为紧急通知。科研结果继续区分计划、来源报告、独立验证和用户验收；Agent 的自述用“报告”表述。重要变化进入语音队列时携带来源、证据阶段及是否需要用户处理，避免仅凭 `decision`／`blocker` 类别就判为 P0。

默认跟随 Mac 已选择的 Agent，并提供播报类别开关；取消来源时撤销其未播放消息。来源不提供的运行、结束或待答状态继续保持未知，不能根据 Bot 最近一条消息猜测生命周期。

实验重点先限定为新的关键结果、重要里程碑、实质结论改变，以及需要用户处理的阻塞或决策；每条必须有新的来源引用和可识别的事实／实验轮次。普通日志、仅提出的实验计划和同一结论的重述不新增语音。模型负责提炼结构化事实，应用负责筛选与投递，不让一个自由的“重要程度评分”直接触发声音。

每条目标约 10–15 秒，包含“哪个任务／项目、发生什么、是否需要处理”；默认上限 30 秒。成稿保留证据限定语，去掉代码块、路径、链接和冗长过程。模型不可用时仍可播确定的“本轮结束”，结果摘要晚到再合并，不能套用上轮结论。

### 播报调度与补齐点

- P1 沿用约 20 秒合并窗口，把同轮结束及随后生成的结果合成一条；P0 不等待摘要。优先级决定下一条，先不因优先级变化打断正在播放的一句话。
- 全局默认两条之间至少间隔 15 秒，按实际播放完成时间计算；已从原先的准备频率限制改为设备实际播放冷却。
- 同会话／轮次／主题／故障周期只提醒一次；连续三次同类故障形成一次提醒，后续同类失败只累计，恢复后才允许新周期。已完成事件跨重启、跨连接方式继续去重。
- 同事实重复摘要不重播；同一实验真正出现新轮次或结论修订时使用新的结果／修订身份，允许再提醒一次，避免同主题被永久压制。
- 取消覆盖排队、合成、传输和播放；已回答、已解决、过期或被更新替代的消息不继续播。静音与安静时段默认对所有类别生效，提供手动停止及最近一条重播。
- 等待／故障 2 分钟、结束／进展 10 分钟、额度恢复 15 分钟到期。首次启动建立基线；历史回填不触发播报。有效期按事实来源时间计算，不能把延迟出队的旧摘要当作刚发生。
- 已修正提前额度恢复的判断，移除必须等旧预计时间到达的条件。新鲜官方观测优先；无法确认恢复原因时只说“额度已恢复”，倒计时归零本身不播“已重置”。

### 音频生成与投递

沿用“Mac 生成、监视器播放”。先用固定短句验收选定的百炼模型与音色，核对 Key 的地域、接入域名、返回格式及错误提示；随后统一为已经实测的 16 kHz／单声道／PCM16。百炼当前 HTTP API 支持 PCM、16 kHz 和所选音色参数，接入地址与地域要求见[官方 API](https://help.aliyun.com/zh/model-studio/qwen-audio-tts-http-api)。

合成缓存按模型、音色、播报稿和相关合成参数区分；修改音色只影响仍有效的未播任务，不重播旧事件。设备音量与云端合成音量分开设置；80 是最初设备听音参考值。0.2.26 起界面直接显示驱动 0–100 档，升级保留实际设置，100% 不再受隐含 80 档上限限制。模型 Key 留在 Mac，设备和中转只接收音频及必要的投递元数据。

生产通道复用并完善现有 `DeviceAudioPort`：

- 能力协商明确声明协议版本、音频格式和长度上限；旧固件继续文字同步。软件能力就绪不等于检测到物理扬声器。
- `audio_start/chunk/end/cancel` 走单独有界通道，分片带序号、CRC、整段散列和有效期；传输上限 30 秒／960 KB。板端使用独立播放任务，不阻塞 LVGL、触摸和心跳。
- USB、LAN、relay 共用投递状态机及 ID。远程使用小窗口／累计确认，避免 2 KB 每片都等待一次公网往返；原视图、触摸与显示控制优先。
- 板端以独立语音 namespace 保存有限投递账本，不改现有配网键。同一投递 ID 在重连及切换连接方式后不重复响；接收完成、开始播放、播放完成分别回执。
- 已经开始但缺少完成回执时标为“结果未知”，默认不自动重放；手动重播生成新的投递 ID。取消必须有界等待真实发送／处理，不能发出一个立即被中止的异步取消调用就算完成。

### 分阶段开发与验收

1. **百炼真实试听**：固定短句 → 正确模型／音色 → 音频格式检查 → 板端试听。独立验收音色、清晰度、响度及错误提示，不混入真实项目内容。
2. **USB 正式播报闭环**：能力协商、30 秒分片、停止／静音、投递账本、播放回执、Mac 类别／静音设置及板端音量设置；用 MOCK 事件验证等待取消、结束合并、重复故障、提前额度恢复和历史不补播。
3. **局域网与异地中转**：接入相同协议，实测掉线、重连、USB／LAN／relay 切换、Mac 与板子重启；确认监视器实际发声、原监控正常、没有重复播报。
4. **逐类启用真实事件**：先等待／审批与本轮结束，再启用经来源校验的重要结果与额度恢复。真实验收只读来源记录，不修改或伪造原 Agent 会话来制造事件。

2026-11-13 已推进正式通道：Mac 0.4.18、板端 0.2.25。实现分类开关、来源时间 TTL、提前额度恢复、优先级队列、结束合并、实际播放冷却、合成缓存、停止／静音／重播，以及经能力协商的 USB／LAN／relay 音频适配。板端 PSRAM 接收完整 PCM 并校验后交独立任务播放；独立 NVS namespace 保存音量、静音和最近 16 个已开始投递 ID，保留原配网键。音量滑杆放在右下角工具中。

本轮已验证：百炼选定音色生成真实 PCM；USB、局域网直连及云中转的正式 start/chunk/end 均收到 playing/played，用户确认首次百炼播报声音正常。连接切换通过共享的视图序号绑定最近实际应用的通道，旧通道回执不能用来认领音频。固件应用区刷写核对成功，刷写前后 NVS/PHY 区字节一致；随后语音账本及用户音量操作会按设计写入独立 namespace。自动化检查覆盖分片窗口、取消发送、等待撤销、去重、提前恢复、播放冷却与滑杆刷新。软件检查：17 项 Python、167 项 Bun、10 项 CTest，以及 TypeScript 类型检查通过。板端音量滑杆的拖动、刷新、保存回调、静音、停止和关闭用 LVGL 输入测试验证；用户尚未手动验收滑杆。播放中停止已收到真机取消回执，切换通道后的取消路由也通过回归测试。云中转通道已用公网服务收到实际音频回执，本轮未把板子移动到另一网络；真正异地拓扑和断电重启去重仍需分别验收。局域网重新配对也确认保存并实际播放成功。

## 范围

先做单向播报：对话本轮结束及简要结果、等待用户输入或审批、需要关注的实验进展、重复故障，以及经确认的额度重置／恢复。语音问答、ASR、声纹、唤醒和连续对话不进入本轮实现。

Mac 是采集、记忆、事件决策和 TTS 的主机；桌面监视器是默认声音输出端。Mac 在宿舍、监视器在工位时仍须能播放。Mac 本机试听只作为显式测试操作，不自动代替设备播放。

## 每个会话的增量记忆

应用自有 SQLite 是规范数据源；Mastra 消费有限上下文，不负责决定哪些科研事实已经成立。Letta 后续通过现有记忆端口适配。

每个 `session_id` 保存：

- `source_generation`：来源身份、inode／轮转标识；替换或截断后不能沿用旧字节偏移。
- `read_cursor`：已安全写入本地增量收件箱的完整记录位置。
- `summary_cursor`：已通过模型输出及引用校验、提交进记忆的批次位置。
- `current_task`：目标、当前阶段及轮次；任务变化生成修订，不靠整段摘要覆盖猜测。
- `latest_results`：近期结果、来源时间、引用和证据层级；区分计划、Agent 报告、独立验证、用户验收。
- `open_questions`：未解决事项的稳定 ID、状态、提出和解决依据；摘要遗漏不代表解决。
- `pending_requests`：来源明确的输入／审批请求 ID、是否阻塞、响应状态；与模型提取的普通未解决问题分开。
- `rolling_summary` 和历史修订：压缩历史背景，保留可追溯引用及覆盖范围。

摄取先持久化去重后的公开消息，再推进 `read_cursor`；摘要、事实修订、引用及 `summary_cursor` 原子提交。TTS 或推理失败均不回退摄取，也不丢失尚未摘要的消息。重启后继续消费相同批次，避免重复写记忆。

每次请求只发送受影响会话的旧结构化状态＋未消费增量＋少量相关引用。按有限预算分页处理，不把几十万 Token 的历史重发给模型。首次历史节选必须标注 partial；需要时在后台分批补历史，与实时通知分开，补入的旧事实不触发新播报。

项目级简报在会话记忆更新后合批生成，只取相关会话摘要。当前最近天数／会话数量上限仍是覆盖边界，不能把范围外的项目说成“全部已监控”。

## 播报事件、优先级与去重

| 优先级 | 事件 | 默认表现 |
| --- | --- | --- |
| P0 | 明确需要用户回答／审批、实际阻塞或重复故障 | 排到下一条；及时提醒，不反复朗读；V1 先不打断正在播放的一句话 |
| P1 | 对话本轮结束、重要实验里程碑／结果 | 合并近邻事件，播报会话名＋简要结果；不逐条朗读工具过程 |
| P2 | 官方新观测确认额度重置／恢复 | 一次简短提醒；不同额度窗口同时变化可合并 |

事件结构至少包含 `event_id`、`session_id`、`turn_id`、`kind`、`topic_key`、`cycle`、`priority`、`source_ids`、`source_at`、`revision`、`expires_at`、`supersedes`。设备投递另外保存 `delivery_id`、目标设备、音频散列、播放状态和回执，不依赖 TTS 文本完全相同来去重。

- 同一会话、同一任务、同类故障使用稳定故障指纹；达到重复阈值后只播一次“任务出现重复错误”。后续十次同类失败只更新计数。明确恢复、用户处理或实质状态改变后关闭该周期；新周期才可再提醒。跨会话故障不能被误合并。
- 等待输入必须基于明确请求及其 ID；收到相应回答或明确取消后立即撤销尚未播放的提醒，阻塞请求恢复也以来源确认的状态为准。异步提出问题后 Agent 仍在继续工作，保留运行状态并单独显示待答提示，也可对该请求提醒一次，不直接判为阻塞等待。不能根据“最后一句像问题”或长时间无消息推断等待。
- 明确区分“定时任务等待调度”和“会话等待用户”。暂停的计划仍遵循现有隐藏规则，不生成等待输入播报。
- 同一 `completion_event_id` 只播一次。结束表示本轮结束，不能等同于整个项目或实验成功。当前轮次摘要尚未生成时延迟短暂合并；模型不可用则只播确定的“本轮已结束”，不套用上轮结果。
- 实验进展必须有新引用且达到重要程度；普通编译、工具调用和重述旧结论不播。Agent 自述结果用“报告……”表述，不能升级为独立验收。
- 额度倒计时归零只触发核查，绝不直接触发“已重置”。新鲜官方观测确认窗口切换且额度恢复后再播；只能证明余额增加时说“额度已恢复”，不猜测原因。首启读取已有额度作为基线，旧缓存不补播。保留现有额度查询频率。
- 默认建议同会话 P1 合并窗口 20 秒、全局播报间隔至少 15 秒；等待提醒 2 分钟过期、结束／进展 10 分钟、额度恢复 15 分钟。均是待实测调整的初值。播放前重新检查是否已回答、解决、过期或被新版本取代。
- 重启不重播已完成记录；离线重连不倾倒历史队列。未播且仍有效的重要事件合并后补一次，其余留在文字消息区。

## Mac 生成、设备播放

链路：`只读来源 → 增量记忆／确定性状态事件 → 有优先级的持久队列 → 脱敏短播报稿 → TTS → 音频传输 → 板端播放器 → 播放回执`。

TTS 采用独立适配器，不绑在摘要模型上。服务地址、声音及 Key 在 Mac 设置，凭据不传给板子或中转。外部 TTS 只接收最终播报短文；不发送完整历史、工具日志或实验文件。具体服务／音色按用户配置；未开启生成时不调用 TTS。

第一阶段候选传输格式为 16 kHz、单声道、16-bit PCM，最终以板级 codec 实测为准；每秒约 32 KB，15 秒约 480 KB。Mac 统一转码，板端不必先引入复杂音频解码器。BSP 默认是 22050 Hz，播放器必须显式协商／配置采样率，不能直接按默认速度播放 16 kHz 数据。

先复用 USB、LAN、relay 的设备身份和鉴权，增加有版本的音频控制与分片协议。升级 relay 和两端的包类型校验，不开放匿名音频 URL，也不让板子访问 Mac 的 loopback 管理接口。语音主机密钥与设备令牌继续分离。

- 控制字段：音频 ID、事件／投递 ID、codec、采样率、通道、长度、散列及有效期。
- 分片带序号、长度和校验；有 ACK、有限重试、背压和取消。设备只接受与当前授权播放任务匹配的数据。
- 视图、触摸、心跳和熄屏／亮度命令优先于音频；有界环形缓存＋独立 I2S 播放任务，不阻塞 LVGL。
- 接收成功、开始播放、播放完成是不同状态；UI 视图 ACK 不能算语音播放完成。
- 网络无法保证严格的物理“恰好播放一次”：设备持久化有限投递账本；已经开始但缺少完成回执的任务记为结果未知，默认不自动重播，允许手动重播，避免断线重复响。
- USB／LAN／relay 切换沿用同一投递 ID，不产生第二份提醒。旧固件未声明音频能力时仅保留文字，不影响原监控功能。

板端工具提供音量、静音／停止、试听与重播最近一条；Mac 提供总开关、类别开关、安静时段和默认输出设备。安静时段默认抑制语音；是否允许指定 P0 越过静音由用户明确配置。显示器跟随熄屏与静音分开设置，避免自动改动现有行为。

## 分步实施和验收

1. 补齐 Codex 明确等待／审批信号：合成测试覆盖提出、回答、恢复、取消及重启；真机会话与板端黄色状态核对。不能通过写入或修改原 Codex 会话来测试。
2. 结构化会话记忆和两个游标：验证单会话增量更新、长历史预算、跨页无丢失、截断／轮转、失败重试、引用和更正追踪。
3. 语音事件队列：以 MOCK 验证十次同类故障只出一次、解决后新周期、重复完成、旧摘要、静音、过期、重启及额度确认。
4. 先用测试 PCM 打通板级扬声器，再经 USB 发送；保持 UI／触摸和心跳正常。完成后接 TTS，并检查听感、采样率、音量和播放回执。
5. 验收 LAN，再将 Mac 与监视器放到不同网络验证 relay：真实由监视器发声、Mac 不作自动播放回退，断线与连接切换不重复播报。

以上阶段分别记录实现、自动测试、编译、传输回执和实际听音结果。仅有 mock／编译／网络 ACK 不算语音真机完成。
